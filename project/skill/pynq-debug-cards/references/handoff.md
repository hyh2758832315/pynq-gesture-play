# 资源交接与恢复

按当前症状选择卡片，先核对触发条件，再采用对应处理。

<a id="e11"></a>
## E11 · 退出超时、owner 保留或 DMA 仍占用

- **症状：**worker/进程停止请求已发出，但通道、借用缓冲或锁尚未释放。
- **核对与处理：**先停止接收新工作，让当前工作完成或使用驱动支持的中止；按实际设备检查 worker、通道和借用者。沿同一 owner 等待/重试释放，条件满足后自动续接请求。
- **完成条件：**旧资源确认释放，新 owner 接管并恢复目标功能。
- **适用条件：**释放条件按设备定义；确认 DMA 停止和借用者归还后再释放 buffer，软件超时用于触发状态核验。
- **来源：**[来源案例](../sources/preflight_cards.txt)。

原始调用身份与来源摘要另见 [E 系列目录](../sources/preflight_catalog.txt)。

<a id="h15"></a>
## H15 · 切页面后部分功能永久不响应

- **症状：**重复 OFF 在 RELEASING 抛错，菜单线程退出，而摄像头/OSD 看起来仍正常。
- **核对与处理：**让同一次释放的重复请求合并等待；异常在所属工作循环处理，并保留有界重试。确认旧资源释放后恢复 owner、输入线程和待完成的页面请求。
- **完成条件：**释放成功后的正常请求可继续执行，迟到回执只更新对应 generation。
- **适用条件：**异常处理维持单一 owner 与交互循环，释放成功后沿原请求恢复。
- **来源：**[来源案例](../sources/menu_recovery.txt)。

<a id="h16"></a>
## H16 · 显示 accepted，却没有 rendered

- **症状：**视频/游戏切换或回传暂停页提交成功，却停在旧画面，或退出后无法交互。
- **核对与处理：**核对共享渲染资源的 owner、请求票据和代际；从 accepted 跟踪到 rendered/完成；退出时恢复原页面的执行和输入权。
- **完成条件：**当前代际完成呈现且交互恢复，旧回执不能释放新资源。
- **适用条件：**业务切换期间仍需跟踪异步在途工作；暂停页命令同样绑定有效 owner 与请求身份。
- **来源：**[来源案例](../sources/preview_owner.txt)。

<a id="h19"></a>
## H19 · 第二次 MMIO 读不返回

- **症状：**首读正常，后续读停在 before-read 记录；软件 timeout 后系统仍失联。
- **核对与处理：**优先回收已有持久日志，核对 boot、位流、HWH、软件与探针身份；用已有同条件对照缩小范围，后续观测围绕 AXI/时钟/复位握手安排。
- **完成条件：**取得确切卡住阶段和响应链路证据后再决定修复点。
- **适用条件：**案例中不同构建存在实板差异，适用结论为 AXI／时钟／复位的分支定位方法；具体根因需由响应链路证据确认。线程超时用于观测控制，AXI 事务终止由硬件协议决定。
- **来源：**[来源案例](../sources/repeat_mmio.txt)。
