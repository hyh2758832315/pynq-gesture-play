## 1. 结论与推荐路线

双音量门槛具有算法可行性，适合固定距离、固定麦克风增益、背景噪声可控的体感游戏。首版把交互定义为“中等音量一次动作 + 较大音量另一次动作”，一次声音最多触发一个动作，而不是继续识别低音调与高音调。用户持续发声不会要求PS维持音量计算，也不会连续触发游戏动作。

两阶段按父子版本顺序推进，各有单独的通过门和回退包：

| 线别 | 硬件 | 软件与玩法 | 用途 |
| --- | --- | --- | --- |
| 阶段一：V0统一无声基线 | 原r8的规范800 bit/HWH，原字节保留 | 10月8日pc-stop母版，方法级合入R703菜单，统一Agent/Studio/启动器/游戏包；先以game2整局闭合 | 形成一个真正统一连接并通过验收的可回退版本 |
| 阶段二：V1轻量声视候选 | 从阶段一对应800等价源新建硬件，增加最小音频判定通道 | 完整继承V0，PL生成音量状态和事件，PS读取并映射游戏 | 在板载麦克风路径上恢复简单、低延迟的声音交互 |

## 4. 双门槛的含义与使用条件

### 4.1 音量与音调

音量反映麦克风收到的信号强度，音调反映声音的基频。低沉声音可以很响，高音也可以很轻。音量门槛方案放弃低音/高音辨识，改成QUIET、SOFT、LOUD三档，并将SOFT、LOUD映射为不同游戏动作。

这是“两条幅度分界线划分三个区间”，不是“两个独立的开关”。LOUD必然也超过较低门槛；不能刚超过低门槛便立即发SOFT，再随着声音变大补发LOUD。首版采用固定短判定窗口和高档优先，一次声段只选一档，事件发出后等安静重武装，避免一声同时护盾与攻击。

双门槛也不区分人声、拍手、风声、音乐和其他人的声音。任何达到门槛的声音均可能触发；定向近讲、固定距离、关闭扬声器回授、适当降低环境噪声属于适用条件。若用户要求嘈杂环境中只识别本人声音，双门槛不足以承担该目标，需要重新评估传感器或识别需求。

### 4.2 固定增益和一次校准

使用固定麦克风位置及codec/ADC增益。若采集链有AGC、压缩或自动限幅，须明确其状态；强AGC会抹平两档音量差异。不能在未核codec配置前承诺两档可分。

进入测试前记录安静背景、中等发声、较大音量三组短样本分布，确认背景与SOFT、SOFT与LOUD有可用间隔。之后保存两个门槛、增益、窗口、状态机参数及配置SHA，运行期间固定；不引入在线自适应门槛。条件不可分时先调整距离/增益或判定场景不适用，而不是无限增加识别规则。

门槛采用已声明位宽和增益下的整数幅值或窗累计值，不标为声压级dB SPL。若PC诊断换算为对数显示，须明确是本项目L1幅度指标的满量程参考值，而不是旧RMS标定。不同麦克风、增益、安装距离下，同一数字门槛对应的实际声压不同。

## 5. PL侧最小音量算法

### 5.1 去直流、绝对值和短窗累加

为满足PS计算尽量少、硬件也尽量简单的要求，主方案改用平均绝对幅值L1，不采用上一草案的S1/S2均方统计。L1只是新的幅度指标，阈值必须按该指标标定，不把旧RMS或音调规则中的数值直接搬过来。

首选沿用已验证采样配置，以48 kHz、20 ms非重叠窗为设计起点，每窗N=960，每秒50窗。采样率、有效位宽、通道选择、符号与对齐必须由冻结接收源及实测确认；不能把I2S槽宽误当有效PCM位宽。

对样本先用一阶定点直流跟踪，再累加去直流后的绝对幅值：

$$
m_n=m_{n-1}+2^{-k}(x_n-m_{n-1}),\qquad y_n=x_n-m_n,
$$

$$
S_w=\sum_{n\in w}|y_n|,\qquad A_w=S_w/N.
$$

直流跟踪仅用加减和移位；每样本统计仅用绝对值、累加和窗计数。门槛在配置阶段预乘N，PL直接比较S_w与N*T，因此正常运行不需要除法、平方、开方、对数、FFT或音高估计。直流跟踪不是人声识别，仍会保留可触发的风噪和环境声音。

48 kHz下k=10可作为最小直流抑制原型参数；它是待验证的滤波配置，不是已验证音质或延迟结果。状态用足够小数位的定点数，差分与绝对值扩位，防止负满量程取绝对值溢出。24位输入若统一到16位，必须声明移位、舍入/饱和与削波检查，不能把格式转换藏在门槛里。

窗口累加宽度按去直流差分的实际最大值乘N计算，而不是只按原PCM位宽计算。初始化先等待codec稳定、直流滤波状态稳定及安静重武装，再允许事件；参数修改使旧累计窗和待处理事件失效。所有滤波、累加、比较、滞回、计时和事件锁存均放PL，PS不逐样本或逐窗重算音量。

| LOUD进入门槛 | 现场标定T_loud，且大于T_soft | SOFT与LOUD分布之间选门槛；不预填通用dBFS值 |
| 退出滞回 | 初始约为各自主门槛的3/4 | 配置时生成固定退出值；用户仍只调两个主门槛，PL只比较整数 |
| 单次分类窗口 | 从首个有效越过T_soft的窗起计3窗，60 ms | 暂缓低档输出，给较大音量确认机会 |
| SOFT确认 | 分类窗结束时连续3窗达到中档且窗内未越过T_loud | 只发一次SOFT_EVENT；有未确认高档扰动时放弃本次而非猜低档 |
| LOUD确认 | 分类窗内连续2窗达到高档，40 ms起 | 提前锁定LOUD_EVENT，取消SOFT候选 |
| 安静重武装 | 连续5窗，100 ms | 同一段持续声最多一次事件；两次声音之间必须回到安静 |
| 新鲜度上限 | 初始沿用100 ms | PS只检查源窗口和事件年龄，不给旧结果续命 |

上述计数与状态转换由PL执行。滞回是固定参数，不是在线自适应。启动、恢复或更换配置后先等待有效安静重武装；麦克风启动爆音不能直接产生攻击。显示优先使用整数幅值或归一化条形值，若需dB标度可由PC诊断端换算，PS实时链不计算对数。

### 5.3 状态与动作

| 状态 | 输出与转换 |
| --- | --- |
| UNARMED | 不产生玩法事件；有效安静连续100 ms且旧事件已处理后进入ARMED |
| ARMED | 首个有效越过T_soft的窗启动一次CANDIDATE，记录声段与采样位置 |
| CANDIDATE | LOUD连续2窗则发一次LOUD_EVENT；否则60 ms到期时仅在SOFT满足完整条件时发一次SOFT_EVENT；其余候选放弃 |
| RECOVERY | 已发或放弃的声段均不再分类；音量继续升高、下降、尾音或持续不变均不追加事件。安静100 ms且事件已确认后重新武装 |
| INVALID/FAULT | 动作中立，清待处理事件并留下失效原因；恢复后重新经过UNARMED，不重放旧声音 |

PL只需窗口计数、稳定计数、短候选计时、安静重武装和事件锁存。事件包含SOFT_EVENT或LOUD_EVENT、声段/事件序号、源采样位置、配置epoch，不要求生产链传输声段结束或计算声段总长度。诊断幅值可低频读取，省去原先供持续玩法使用的时长字段与结束事件。

固定分类窗是有意的延迟/分类折中：若用户先中等音量超过60 ms后才明显增大，该声段仍保持先前选定档位，不升级或补发。若要求按整段最大音量分类，就必须等声音结束，增加延迟；首版不采用该路线。这个边界必须进入真人操作与缓慢幅度上升负例测试，不能宣称整段峰值分类。

20 ms窗和60 ms候选只给出设计时序；实际声起到档位确认还包含窗口对齐与滤波影响。采样位置由PL计数，不能用PS轮询次数或游戏tick代替。缺窗、跨epoch、时钟跳变、暂停和配置变化使当前候选失效；缺失区间不推断为安静。

削波通过触及数字上下限的样本计数单独检查。持续严重削波说明增益或声源距离不合适，该条件应失效并提示调节，不默认为可信LOUD。短脉冲、削波与有效大声的边界由采样回放和真人数据确定。

## 6. 阶段二的唯一主硬件路径

### 6.1 从阶段一800源新建PL音量判定通道

原800规范硬件缺少本方案所需板载声音通路；单改PS软件无法在相同bit上凭空增加I2S能力。阶段二需要独立硬件候选，但不引入B00视觉下沉或900完整PCM链。

```text
板载codec/ADC
  -> 原来源核准的MCLK/I2S接收
  -> PL去直流/绝对幅值短窗累加
  -> PL双门槛/短候选窗/稳定计数/安静重武装
  -> PL状态快照 + 锁存事件/序号 + 故障
  -> 跨时钟原子读取/确认
  -> PS有效性检查与一次性事件转发
  -> 显式音量输入 -> 游戏 -> SceneCompiler -> GPU/HDMI
```

与900相比，候选不需要音频PCM SG DMA、描述符、音频DDR master、voice_memory_smc及PCM大块IPC。保留必要的codec IIC、MCLK、接收时钟、复位和故障检测；是否能合并任何控制器由真实连线和地址能力决定，不凭名称合并。

注意区分PS的控制主口M_AXI_GP0与供PL主设备访问DDR的S_AXI_GP0。本候选音频仅走控制/统计通道，不因音频而启用900的DDR S_AXI_GP0通路。原视觉/GPU的五个DDR master映射、IRQ、时钟和约束保持基线合同。

PL每样本只需要加减、移位、绝对值和累加，每窗运行两档比较及几个短计数器。主算法不需要乘法器或DSP，但最终LUT/FF、控制集、时钟和IIC成本必须以综合实现报告为准。PL只处理声音语义，不放入游戏护盾、攻击或机关规则，玩法仍由游戏消费显式输入。

PS按约50 Hz读取几十字节状态，异常事件另有锁存确认；无需读取PCM或每窗特征数组。若完整状态为64字节，50次/秒的净载荷约3200字节/秒；这不包含AXI读事务、轮询与协议开销，不能当作总带宽实测。诊断幅值可低频读取，正常玩法只消费档位、事件和必要有效性字段。

### 6.2 最小接口与安全合同

- 配置只需两个主门槛、从主门槛预生成的退出值、固定窗长/稳定计数、使能/重武装及配置epoch；不支持在线规则脚本、频谱参数或自动阈值学习。
- 只读状态至少包含硬件身份、epoch、窗口/采样计数、当前状态、armed/event_pending和削波/失步/溢出故障；诊断幅值为可选低频字段，不要求SOFT持续信号或声段总时长。
- 单次事件仅为SOFT_EVENT或LOUD_EVENT，绑定事件/声段序号、源采样位置和档位。首版采用一个待确认事件槽；匹配序号的ACK释放后仍须满足安静条件才能重新武装。未ACK时不接纳新声音，过期进入显式FAULT；禁止覆盖旧事件、先发单周期脉冲再希望PS碰巧读到，或扩大队列掩盖消费阻塞。
- 多寄存器状态必须对应完整快照，事件在ACK前保持稳定；采用锁存后显式确认或前后序号校验，不能读取半新半旧字段。
- 跨时钟用已审阅的握手保持或成熟异步FIFO，完整验证多位载荷稳定和复位行为，不把每位各自两级同步当作原子快照。
- PL每窗完成决策，PS不必逐窗重算或保存所有诊断幅值，但不得跳过锁存的玩法事件。100 ms新鲜度和ACK预算独立约束，轮询超时或事件超龄即中立/FAULT，不伪装连续消费。
- 建立采样计数/硬件时钟到PS单调时间的锚点和误差边界，分别核对最新窗与事件年龄；不能把寄存器读取时间标成采集完成时间。epoch变化或映射异常立即失效。
- 音频下游变慢时，禁止通过反压停住无法暂停的I2S/ADC源。事件槽满、I2S失步、样本数异常必须可观测。
- AXI状态口使用既有系统控制时钟，接口就绪不依赖I2S/MCLK工作或音频数据域完成启动；音频未就绪时正常返回NOT_READY/FAULT，禁止把PS读事务悬挂在音频复位上。先验证独立复位状态与释放，再访问受影响接口，借鉴[B00复位缺口记录](bringup/2026-10-17_b00_startup_diagnosis.md)，不复制同类无响应路径。
- 正常停机顺序为禁止新玩法事件、停止新接收/判定、确认源侧静止或隔离、确认/清理本epoch剩余事件、最后释放本组件资源与owner。取消PCM DMA不等于取消复位、IIC和线程收尾责任。

## 7. PS、输入协议与游戏设计

### 7.1 小型独立音量后端

复用单Agent独占Overlay的结构，新后端不启动原音调特征actor、FFT处理或PCM波形观察进程，不因音频加载NumPy或SciPy。Agent内轻量有界读取器按约50 Hz取状态/事件；PS只检查身份/epoch、序号/年龄、故障，转发一次事件并ACK。游戏tick只读取已发布的完整输入，不在Scene提交锁内等待声音I/O。

明确分工：PL负责滤波、幅值、门槛、短候选窗、去抖、安静重武装和事件锁存；PS负责安全、连接和游戏输入映射。PS不遍历PCM、不做RMS/FFT/相关计算、不重复运行音量状态机，也不按声音窗口创建进程。读线程、MMIO和生命周期仍属于同一个Agent所有权。

以可追溯结构表示valid、run/epoch、配置SHA、来源窗口、采集时间、事件档位和事件/声段序号。PL到Agent、Agent到游戏采用分开的确认边界：Agent先将有效事件放入本消费者epoch内的单个本地待消费槽，再ACK硬件；游戏按序号只消费一次，形成独立回执。本地槽未空时不覆盖或继续取下一事件；超龄或容量冲突显式失效。硬件ACK只代表安全取走，不冒充游戏已消费或Scene已完成；Scene/GPU完成仍沿用原有独立回执。

状态、诊断和事件采用不同发布策略：状态可读最新快照；PL按完整窗口决策；游戏事件从锁存槽确认并按身份转发；诊断最多5至10 Hz且默认不生成波形/频谱。无PC时Agent本地闭合，Studio仅订阅，断开PC不停止或改变声视采集。菜单、暂停和不使用声音的game2按新消费者epoch显式禁用玩法事件，重新进入游戏先清旧事件并重新武装。

### 7.2 明确区分音量信号与ToneSignal

现有Game SDK 1.1的ToneSignal包含frequency_hz等音调语义。新方案不得用伪造300/1500 Hz去套旧游戏，也不得把未测频率标成真实识别结果。

实施时优先新增可选VolumeSignal输入，音调字段保持原义。新候选需要SDK minor、输入schema及HELLO能力协商；具体版本号先核现有注册再分配。旧VVG、旧时间线和原黄金用旧合同继续运行，新音量游戏包显式声明新能力，旧runtime在运行前拒绝不支持的包。

输入日志和回放增加音量状态、声段/事件身份、来源时间、配置SHA；确定性测试使用明示的合成音量输入，真实采集和回放完全隔离。旧音调黄金只说明旧玩法，不作为新音量候选的通过证据。

### 7.3 游戏映射

| 游戏 | V0范围 | V1建议交互 | 改动与验收重点 |
| --- | --- | --- | --- |
| game2猜拳 | 首个完整纯视觉闭合对象 | 音频默认禁用，玩法保持 | 防止全局音频接入影响已有三态手势 |
| game1横版 | 视觉方向与跳跃；完整无声玩法另建候选 | SOFT_EVENT触发一次固定时长护盾，LOUD_EVENT攻击一次 | 游戏只新增固定tick倒计时与已有能量/冷却规则；不要求玩家持续中等发声，不采用永久护盾开关 |
| game3共鸣王国 | 选角、移动、跳跃；声音机关尚未被替代 | 门附近LOUD_EVENT开门一次；升降台附近SOFT_EVENT启动一轮自动升降 | 游戏复用既有运动/碰撞/承载逻辑，以简单状态和tick计数驱动；一声只消费在一个有效目标，不依赖持续发声 |

game1护盾可先研究36个逻辑tick，60 Hz设计下约0.6秒；游戏实际tick速率另报，不保证墙钟时长等于0.6秒。game3采用一次“上升、顶部短停、返回”固定流程，运行中重复事件按既定规则忽略且不叠加速度/行程。具体tick参数与关卡可达性在新候选黄金中固定；这些小型玩法计数属于原有PS游戏逻辑，不是把声音统计或分类搬回PS。

持续SOFT不作为首版实现项、验收项或自动后备模式。双档单次通过后，若确有玩法需求，再经单独决策扩展持续信号；当前不为其保留额外时长规则、结束事件或复杂可配置模式。两档本身若不可分，应先调整固定增益/距离或缩减需求，不以增加PS识别补救。

保留[game1原音调适配](../games/game1/src/input_adapter.py)与[game3原声音机关](../games/game3/src/rules.py)原字节及原黄金。新候选使用独立包身份、版本和断言用例，不覆盖原冻结游戏。纯视觉交付若包含game1/game3全关卡，另行设计可达的视觉机关或关卡变化；仅停音频不能算完整玩法闭合。

## 8. 预算、效果与失败边界

### 8.1 可以合理预期的效果

相较PS原特征链，PL每20 ms形成一次状态，并在确认边沿锁存事件。PS由原来的采集/特征/判决链缩减为低频小状态读取、安全检查和游戏转发，同时省去音频PCM搬运、cache同步和大块IPC，值得优先验证。

资源回收分两类：PS计算量从架构上明显减少，实际成本仍需测量；PL净资源减少必须通过新硬件实现确认。PL删除SG/DMA互联后可能降低资源和控制集压力，新增IIC、时钟、音量判定和CDC也有成本；最终净变化由实现报告给出。

### 8.2 初始工程预算

下列是候选准入目标，不是当前已达结果。未达时保留失败和分项成本，再决定优化或回退，不修改数值冒充通过。

| 指标 | 建议初始目标/记录方式 |
| --- | --- |
| 音量后端PS成本 | 读取、安全检查、发布/ACK与输入转发总计优先目标不超过0.01个核，即每秒10 ms CPU；超过先分项测量，不把计算搬回PS或直接放宽预算 |
| PL统计/判定频率 | 实际连续50窗/秒；记录来源序号、样本数、事件与溢出，不以配置值充当实测 |
| 来源新鲜度 | 首版保留100 ms年龄上限；过期进入中立，记录首个故障窗口 |
| SOFT/LOUD声起至游戏动作 | 两档分别统计，p95不超过150 ms作为原型目标；区分采样对齐/候选窗、PS读取、游戏tick与Scene完成，不从配置值推算实测 |
| 连续发声重复触发 | 一段有效声音最多1次事件；音量后升/尾音不补发，安静重武装后新声音才产生下一次 |
| 整机CPU余量 | 用低干扰采样记录系统及各组件均值、p95/最大短窗占用和最长无进展段；持续超过双核容量或反复期限失效即不通过 |
| GPU/游戏 | 分别记录tick、Scene完成、present与控制更新率；60 Hz配置或HDMI刷新率不等于实测60 FPS |

在同一候选、同一场景、同一采样方法下比较V0与V1，并记录观察者自身成本。历史识别0.52至0.55核只能作为旧方案预算背景，不能直接宣称新方案节省0.5核或必达60 FPS。

### 8.3 主要风险

| 风险 | 处理与退出条件 |
| --- | --- |
| 噪声或其他声源触发 | 定义演示环境；观察误触发；超出场景能力则回退纯视觉或重新讨论需求 |
| 距离/增益变化、AGC、削波 | 固定配置；校准与有效性检查；增益变更必须新配置epoch |
| 音量档位不可分 | 先取真实分布；无足够间隔则拒绝双档验收，不靠不断加规则掩盖 |
| 大声先越过低门槛产生双动作 | 短候选窗、高档优先、一声一档、安静重武装；缓慢增大的声段按窗口内档位处理并如实记录 |
| PS读慢或事件未确认 | PL锁存事件、单本地待消费槽、匹配ACK和100 ms年龄检查；未ACK不重武装，超龄显式失效 |
| codec/IIC或AXI初始化卡住 | 冻结来源、分阶段就绪、可响应复位协议和有界控制；算法简化不替代驱动修复 |
| 新硬件时序或资源失败 | 在隔离工程实际综合实现、报告CDC/DRC/方法学；回退V0，不放宽既有约束 |
| 退出或复位释放不完整 | 确认线程、接收端、快照与owner状态；未知时保留资源，禁止自动重载 |

## 9. 多步骤执行方案与通过门

### 9.1 共用执行规则

仍然只有两个大阶段，下面A01至A07、B01至B10是阶段内顺序步骤，不是并行推进的17个改造项目。2026-10-19已获授权实施上板前范围，A01-A03离线完成，A04-A07与B01-B10仍为NOT_STARTED；当前进度与证据见9.6，本文不扩展部署或硬件操作授权。

每步在一个独立证据目录记录父版本/输入SHA、操作、预期与实际、错误原文、复验和产出SHA，状态只取NOT_STARTED、ACTIVE、PASS、FAIL或BLOCKED。只允许一个实施步骤ACTIVE；失败先修复同一步并复验，不在失败现场叠加新模块，不复用旧收据给新源盖章。

### 9.2 阶段一：统一、连接并冻结无声基线

本阶段的任务是把多个来源做成一个实际验证过的系统，音频服务、PCM采集与原特征进程全程不启动。
