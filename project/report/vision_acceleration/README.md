# 视觉 PL 加速：计时与板端结果

视觉前处理从逐帧往返改为采集侧连续流：PL 完成区域缩减、颜色分割、形态处理和双掩码对齐，PS 继续执行轮廓与手势判别。这里分别提供硬件内核计时和板端新识别结果更新率，正文见[设计报告第 5.2 节](../设计报告与大模型协作记录.md#52-视觉前处理下沉)。

## 内核计时

Vivado/XSim 2026.1，100 MHz，640×360，每个内核连续处理两帧；输入持续供数、输出始终 ready。计时取首个输入握手至末个输出握手，包含内部停顿与排空。

| 内核 | 每帧周期 | 每帧处理跨度 / ms | 首输入至首输出 / μs |
| --- | ---: | ---: | ---: |
| BGR→HSV＋阈值掩码 | 230403 | **2.30403** | 0.04 |
| 9×9 膨胀＋5×5 平滑＋双掩码对齐 | 237161 | **2.37161** | 39.02 |

换算：`ms = elapsed_cycles / 100000`。每核两帧的计时一致。颜色输入为 BGR=(128,128,128)，形态输入为零掩码；测试检查所有输出像素、帧标记、数量、无故障与看门狗。日志含 `TEST_PASS PL_KERNEL_TIMING`，两核各输出 460800 个像素。

相机节拍、DMA/DDR 和 PS 调度在此核内计时之外，流水段之间可重叠。原路径板测颜色阶段 66.940 ms 含颜色核往返和同帧参考检查，形态学阶段为 32.230 ms；它们描述应用阶段成本，与核内跨度分别列示。

## 从源码复现内核计时

环境：Vivado/XSim 2026.1，器件 `xc7z020clg400-1`，启用 Vivado 自带 XPM FIFO。先启动已配置 Vivado PATH 的终端，在仓库 `project` 目录执行：

```powershell
vivado -mode batch -source report/vision_acceleration/run_kernel_timing.tcl
```

脚本在本目录的 `work/` 创建独立仿真工程。预期输出为 `work/kernel_timing.sim/sim_1/behav/xsim/simulate.log`，其中四条 `TIMING` 的 `elapsed_cycles` 按上表重复两次，末尾出现 `TEST_PASS PL_KERNEL_TIMING`。仿真约在 4.81658 ms 的模拟时间正常结束；该时间不是工具运行的墙钟时间。

下一步：将重跑日志中的周期、像素数及 PASS 标记与随附 CSV／日志摘录核对；板端系统复现按[完整报告第 9 章](../设计报告与大模型协作记录.md#9-从零复现与验收)执行。通过 ROSS 使用该 Tcl 时，应选择独立空闲 Vivado 会话。
