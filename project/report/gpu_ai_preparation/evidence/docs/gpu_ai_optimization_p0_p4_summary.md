# AI 辅助 GPU 优化总结：P0 至 P4

## 1. 总体结论

本项目在 PYNQ-Z2 的 Scene2D GPU 上，通过 AI 辅助分析、RTL 改写、独立黄金回归、时序诊断与产物核验，完成四阶段优化：Tile 描述符缓存、Blit/Tile 单像素流水、条件性双像素、Scene 上传与渲染重叠。

在相同 100 MHz 渲染时钟下，代表性同负载 RTL 对照获得以下结果：

- Tile 缓存叠加单像素流水：13,860 → 2,340 周期，周期减少 83.12%，加速 5.92 倍。
- Blit 单像素流水：1,281 → 261 周期，周期减少 79.63%，加速 4.91 倍。
- 核心栅格双像素：57,909 → 28,974 周期，周期减少 49.97%，加速约 2 倍。
- Scene 预上传：下一 Scene 的 520 个内部上传握手在当前渲染期间完成，关闭重叠时为 0。

P0 到 P4 的整机 PL 资源累计增加 941 LUT（6.71%）、529 FF（2.32%），BRAM 从 62 降到 60 Tile，DSP/MMCM 保持 2/2。最终实现后 WNS/WHS 为 0.029/0.052 ns，满足既有工程门禁。优化采用已有双命令 bank 和 framebuffer，保持通用 Scene、绘制顺序和资源容量。

上述性能数值分别对应各自同负载对照。资源采用 P0/P4 整机直接对比；渲染周期采用阶段开关对照；板端完整游戏帧率、功耗及多模态并发属于后续实测指标。

## 3. 四阶段优化路线

| 阶段 | 主要瓶颈 | 实施内容 | 已验证效果 |
| --- | --- | --- | --- |
| P1：描述符缓存 | 同一 Tile 的逐像素描述符重复读取 | 复用描述符寄存器，保存有效位与完整地址 tag；新命令及复位失效 | 大 Tile 场景周期减少 31.17% |
| P2a：Blit 单像素流水 | 素材请求、响应和写入串行等待 | 浅上下文流水携带地址、nibble 和有效位，末请求排空 | 连续合法不透明段 1 像素/拍，256 写场景加速 4.91 倍 |
| P2b：Tile 单像素流水 | 描述符与逐像素源定位串联 | 锁存源原点和 descriptor run 边界；Tile/行切换及错误先排空 | 连续合法段 1 像素/拍；叠加 P1 的同负载累计加速 5.92 倍 |
| P3a：Tile 双像素 | 单字节 framebuffer 写入限制配对吞吐 | 16-bit 写 / 8-bit 读与独立字节掩码；同 byte 双 nibble；按有效 lane 顺序统计 CRC | 配对条件下 2 像素/拍，核心长 Tile 加速 1.46 倍；BRAM 减少 2 Tile |
| P3b：Blit/CLEAR/FILL 双像素 | 其他绘图 opcode 仍逐像素执行 | 通用 Blit 配对、CLEAR/FILL 行内双写，独立 lane 掩码；拆分尾界与 CRC 关键路径 | 代表性核心栅格场景加速约 2 倍 |
| P4：上传与渲染重叠 | 当前帧渲染期间下一 Scene 上传等待 | 锁定 renderer 读 bank，最多一个 READY；结果 hold/release；资源 generation 栅栏；有界软件 ticket | 下一 Scene 520 个上传握手与当前渲染真实重叠 |

P2a/P2b 同属第二阶段，P3a/P3b 同属第三阶段。双像素路径按合法对齐、源 byte 和行内边界选择；透明 lane 独立控制，其他合法场景沿单像素路径执行。资源更新先 drain 并等待 generation 实际提交，VIDEO 每帧素材更新保持串行。

## 4. P0 与 P4 最终直接对比

### 4.1 整机资源与时序

| 指标 | P0：冻结 C6I | P4：最终累计优化 | 变化 | 相对 P0 |
| --- | ---: | ---: | ---: | ---: |
| LUT | 14,025 | 14,966 | +941 | +6.71% |
| FF | 22,845 | 23,374 | +529 | +2.32% |
| Slice | 7,262 | 7,538 | +276 | +3.80% |
| BRAM Tile | 62 | 60 | -2 | -3.23% |
| DSP | 2 | 2 | 0 | 0% |
| MMCM | 2 | 2 | 0 | 0% |
| 渲染时钟，MHz | 100 | 100 | 0 | 0% |
| 像素时钟，MHz | 74.25 | 74.25 | 0 | 0% |
| WNS，ns | 0.057 | 0.029 | -0.028 | 两版本满足既有 setup 门禁 |
| WHS，ns | 0.050 | 0.052 | +0.002 | 两版本满足既有 hold 门禁 |

按器件容量折算，LUT 占用约 26.36% → 28.13%，FF 占用约 21.47% → 21.97%，Slice 占用约 54.60% → 56.68%，BRAM Tile 占用约 44.29% → 42.86%。Slice 单独体现物理布局占用；功耗采用后续实际测量。

最终资源低于本轮上限 15,110 LUT / 23,844 FF，分别保留 144 LUT / 470 FF 的门禁余量；BRAM/DSP/MMCM 符合 60/2/2 上限。门禁余量表示本轮预算差值，器件剩余容量按上面的占用率单独评价。

### 4.2 执行与调度能力

| 维度 | P0 路径 | P4 累计优化路径 |
| --- | --- | --- |
| Tile 描述符 | 逐候选读取 | 同一描述符 run 内缓存复用 |
| Blit/Tile 执行 | 多状态串行请求与写入 | 单像素浅流水；满足配对条件时双像素 |

## 5. 性能测量与优化贡献

### 5.1 渲染周期

加速比 = 对照周期 / 优化周期；周期减少比例 =（对照周期 - 优化周期）/ 对照周期。100 MHz 下每周期为 10 ns，换算时间为对应测试的渲染区间。

| 同负载对照 | 对照周期 | 优化周期 | 周期减少 | 加速比 | 对照与测量层级 |
| --- | ---: | ---: | ---: | ---: | --- |
| P1，size16、3×2 Tile | 13,860 | 9,540 | 31.17% | 1.45 倍 | Tile 单元，缓存 off/on |
| P2a，256 次不透明 Blit 写入 | 1,281 | 261 | 79.63% | 4.91 倍 | Blit 单元，流水 off/on |
| P2b，同一 size16 Tile 负载 | 9,540 | 2,340 | 75.47% | 4.08 倍 | 缓存固定开启，Tile 流水 off/on |
| P1+P2b，同一 Tile 负载累计 | 13,860 | 2,340 | 83.12% | 5.92 倍 | 原 Tile 路径至缓存+单像素流水；P2b 阶段证据 |
| P3a，核心长 Tile 场景 | 813 | 557 | 31.49% | 1.46 倍 | 前述优化固定开启，Tile pair off/on |
| P3b，核心不透明栅格场景 | 57,909 | 28,974 | 49.97% | 2.00 倍 | Tile/cache/pipeline 固定开启，Blit/solid pair off/on |

代表性时间换算：Tile 缓存+流水负载为 138.60 → 23.40 微秒；Blit 单像素流水负载为 12.81 → 2.61 微秒；P3b 核心栅格负载为 579.09 → 289.74 微秒。每行按其明确的对照开关解释，跨负载收益分别展示。

这些周期是各阶段归档的 RTL 仿真实测。P4 沿用已验证的渲染优化，新增上传调度协议；完整 P0/P4 游戏帧性能留给同负载端到端回放。720p60 是输出扫描模式，实际游戏提交/呈现 FPS 另行量测。

## 7. AI 辅助优化的实际作用

AI 的贡献体现为在明确约束下组织并执行“提出局部假设 → 小改动 → 黄金回归 → 时序/资源反馈 → 局部修复 → 整机与身份验收”的工程闭环。用户确定目标、授权范围和预算，AI 辅助分析及实施，Vivado/XSim、独立 oracle、真实 XPM 和软件测试提供验证证据。

| 实际案例 | AI 辅助分析与修复 | 复验证据 |
| --- | --- | --- |
| Tile 流水组合链过长 | 将源原点、descriptor 水平终点前移锁存，拆分逐像素定位和尾界链 | 同负载回归保持，最终单像素流水局部 OOC WNS/WHS=0.281/0.121 ns |
| 双像素有序 CRC 关键路径 | 以原 CRC 函数生成固定 GF(2) 掩码，启用时采用并行 XOR 归约 | 独立逐 bit oracle、透明 lane、取消前缀和立即重试通过 |
| Tile 双像素冗余尾界 | 在已验证偶数/幂次合同内复用 run 边界及 word 尾界 | 消冗后八组合及核心回归通过，整机 LUT 从失败轮 14,629 降到通过轮 14,550 |
| 通用 Blit 奇 local 行尾 | 按 Blit 实际裁剪和候选坐标修复尾判断 | 负坐标、奇目标、stride、flip、掩码与独立 oracle 通过 |
| P4 done/hold 控制边界 | 识别 busy 撤销与父模块 hold 锁存之间的窗口，增加 done 启动门控 | 520 握手重叠、呈现、结果保持与边界回归通过 |
| 软件流水的真实工厂与所有权 | 能力核验后启用有界 ticket；异常保留首错误，worker/DMA 存活时保留 owner | 真实工厂、drain、计数、关闭故障注入测试通过 |

最终效果是以较小寄存器和控制逻辑增量，改善访存复用、流水吞吐、像素并行度和跨帧调度，同时保持游戏渲染合同。失败日志、修复轮次、黄金和产物 SHA 形成可审计链。开发工时节省比例、AI 相对人工的效率倍数与功耗变化采用专门评估；当前展示指标为实际设计性能、资源及验证结果。

## 8. 验证与证据

- 功能：各阶段保留原有序写入、count、CRC 和错误语义；P4 最终矩阵 18 份仿真日志通过，覆盖 off/on、真实 XPM 扫描、bank、资源和完成边界。
- 软件：P4 选定 10 文件 128 个测试及 4 个子测试通过；关闭安全增量四文件 87 个测试通过。两轮按各自范围记录。
- 整机：最终 TNS/THS 和失败端点为 0；内部 unconstrained endpoints 为 0。DRC/methodology/CDC 保持既有质量边界，原四个输出缺 delay 范围保留。
- 身份：P4 的 BD/HWH/manifest BUILD_ID、七开关及 GPIO 合同一致；XSA 主 HWH 与外部逐字节一致，完整 bit 配置体 4,045,564 字节一致。旧 20 个阶段产物 SHA 保持。
- 工程：每阶段独立构建入口、BUILD_ID 和输出；经验写入仓库 Skill 源，再安装并核对部署 SHA。原工作区内容保留。
