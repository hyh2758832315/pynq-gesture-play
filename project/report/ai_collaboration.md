# 大模型协作：从设计判断到可验证实现

团队确定应用行为、软硬件接口和资源目标，模型辅助分析实现方案与边界用例，再用仿真、实现报告和板端结果选择方案。以下为三个关键设计过程的真实对话节选；设计结论与验证结果另行整理，并链接到源码和复现入口。

## 1. 手势跟随：消费最新状态，区分未识别与无手

开发者，2026-10-29：

> 3s后无论是否有手势变化都要变成/保持新识别的手势

模型答复节选：

> 我会把 UNKNOWN 改为保持上一已识别姿态；明确无手时才回 default，仍只保留最新状态，不排队。

开发者补充：

> default是不需要保持时间的

**设计收敛。** 将跟随定义为状态更新：动作获批时启动间隔计时，到期读取最新有效状态，相同姿态继续保持，新姿态进入下一次动作。进一步将三态、暂未识别、明确无手分开处理，避免识别闪烁触发多余回位；default 不占用下一次有效手势的等待间隔。动作执行与视觉发布分别运行，接收端保留一个最新观测，不积累待播放手势。

**验证与实现。** 离线用例覆盖动作期间换手势、到期后的最新状态消费、来源恢复与页面权限交接；再通过 Studio 装载进行三态连续切换验证。当前两项和三项 GPU 配置的板测均确认菜单、游戏与灵巧手跟随正常。

## 2. GPU：在资源预算内形成并行优化路线

开发者，2026-10-03：

> 根据我们的需求，分析gpu提升并行的优化方法以及可行性和资源占用

GitHub Copilot 答复节选：

> 推荐路线：Tile 描述符缓存 → Blit/Tile 单像素流水化 → 条件性 2 像素/拍 → 上传与渲染重叠。暂不优先采用多绘图核。

> Tile 先缓存当前描述符，跨 tile 或配置变化时更新；无需复制 Tilemap。

> 必须携带目标地址、颜色、有效标志等上下文，并在命令结束时排空流水，保持覆盖顺序。

开发者明确资源与通用性要求（同日，节选）：

> 确保不会大量占用pl资源和影响gpu的通用性，仍可以实现不同游戏的渲染，然后开始优化

GitHub Copilot 将约束落实为实现规则（节选）：

> 复用 `active_tile_descriptor`，新增有效位与完整逻辑描述符地址 tag，避免低位截断误命中。

> 每次接受新命令和复位时失效；只缓存校验通过的描述符。

> 当两个源像素共用一个 INDEX4 字节、目标位于同一对齐写字、tile 语义允许时走双像素快路径；其余走单像素路径。

GitHub Copilot 第一阶段实现反馈摘要（同日）：

Tile 描述符缓存完成后，局部增量为 27 LUT、25 FF，BRAM/DSP/MMCM 无新增；核心测试由 156 降至 138 周期，写入顺序与 CRC 一致。

**设计收敛。** 团队将优化目标明确为提高并行效率、控制 PL 资源增量、保留不同游戏共用的渲染接口。由此选择逐层复用现有数据通路：缓存消除重复描述符访问；浅流水让多个像素处于不同执行阶段；条件双像素复用同一索引字节和对齐写入，通用边界继续走单像素路径。跨帧上传重叠作为独立扩展阶段，单独验证命令 bank 与资源代际交接。

**验证落点。** 2026-10-03 的缓存阶段通过同输入关闭／开启对照，核心测试周期由 156 降至 138，有序写入与 CRC 保持一致；局部资源增量为 27 LUT、25 FF。随后阶段继续用透明、裁剪、翻转、行尾及流水排空用例核验行为，并检查整机资源与时序。各阶段的设计和验证为后续系统选择优化组合提供依据。

## 3. PYNQ Skill：把验证经验变为可复用工具

开发者，2026-10-31：

> 继续，但是验证场景选取pynq的pl比较好

模型答复节选，2026-11-01：

> 它会读取原模块的完整输入／输出声明，给现有测试台挂上原版参考实例，并核对实际参数，避免漏比端口或用错参数后误报通过。

模型复核反馈节选：

> 修订后的完整复跑已通过：原测试、28,761 次附加全输出比较和资源／时序门槛均正常

**设计收敛。** 包完成时的 CRC 与字节数断言负责检查协议结果，全输出比较补充复位、空闲和停顿期间的行为检查。工具从冻结参考、候选源码与实际实例参数生成监视器，检查仿真完成状态与工具日志；同时校验参考依赖，保证比较双方的身份清晰。工程集成中积累的诊断方法整理为 20 张 PYNQ 排错卡片，按症状组织适用条件、检查步骤和完成标准，并关联验证依据，便于在后续工程中复用。

**验证与复用。** 在 `scene2d_upload_sink` 的受控故障注入中，仅改变复位输出，以检验包级断言之外的检查覆盖率。全输出检查在 5.001 ns 定位差异，原版与行为等价变体均通过。工具用于 `scene2d_return_source` 优化时完成 28,761 次附加比较，支持验证 FF 从 191 降至 167 的实现。使用者替换源码、测试台、实例与器件配置即可复用，独立示例和搬迁验证随包提供。

## 可复用协作流程

1. 用可观察的输入输出行为描述需求，并确定性能、资源和时序目标。
2. 模型提出修改候选，开发者选择验证范围和组合顺序。
3. 用共同输入、参考输出与工具报告验证候选，按反馈修正参数、依赖或边界逻辑。
4. 通过标准部署入口完成板测，将有效方法整理为构建脚本、测试和 Skill。
