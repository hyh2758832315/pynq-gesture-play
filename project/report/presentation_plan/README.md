## 每段最值得展示的机制和指标

1. **直驱灵巧手**：PYNQ PS 经 USB 串口及 SDK 控制 17 电机，驱动不依赖 PC。
   将独立供电线与通信线分开画。不要画成 PL GPIO 直接产生 17 路 PWM。
   通信标注“串口配置 1 Mbaud”可按实际配置核对；它不是实测有效吞吐率。
   自由度用关节运动箭头配实拍；17 电机数量不直接等同已确认的 17 个独立机械自由度。
2. **视觉识别**：PL 固定前处理及双掩膜，PS 轮廓/凸包/凸缺陷与分类。
   使用同一帧的原图、掩膜和分类对照；指标为实际识别 FPS、分类正确率、无手误触发和 P95 延迟。
3. **HDMI 跟随**：独立 OSD 的最新位置、握拳状态与应用画面叠加。
   画出应用暂停时 OSD 仍更新的分支；测物理手移动到屏幕位置变化的时间及位置抖动。
4. **实体跟随**：输入只保留最新状态；动作获批时开始 3 秒窗口，完成后处理当前状态，同态保持，default 不另占 3 秒。
   用时序图显示“忙中变化→最新槽被覆盖→下一可执行时刻消费”。分别标识调度等待与实际运动时间。
   运行时无持续位置反馈，图中不要画出每阶段持续到位回读的控制闭环。
5. **GPU 视频渲染**：分清视频准备/解码与 PL 图形呈现；无证据时不把 PL 标为 H.264 硬件解码器。
   画出命令缓冲、资源缓冲、显示双缓冲的不同职责，而不是统称“双缓冲”。
   320×180×8-bit×2 = 115,200 B 是逻辑双帧缓冲容量；BRAM 实际占用另由综合报告给出。
6. **游戏流畅度**：实拍持续运动，统计真实呈现帧间隔、输入响应、长停顿、丢帧或重复帧。
   720p60 仅说明 HDMI 扫描；设计 tick 目标也不能替代实际更新率。
7. **画板流畅度**：图示驻留背景/固定像素画布，只更新变化内容，避免图形对象与上传无限积累。
   测盖印延迟、长时绘画的帧间隔、对象/缓冲容量、每次更新上传字节。
8. **Studio**：展示同一内容包、用例和逻辑时间的 PC/PYNQ 验证链路。
   指标为标准安装成功、相同内容身份、逐 tick 结果一致与启动/返回恢复，而不是堆叠窗口数量。

## 灵巧手通信图的准确画法

上层：视觉生产者 → 单个最新状态槽 → owner/调度器 → 预编译阶段目标 → USB/SDK。
下层时间线：启动检查 → 播放阶段目标并按时序等待 → 正常保持/接受后续状态 → 退出卸力确认。
将 READ/WRITE 用不同箭头区分：正常播放省去持续位置轮询，启动与退出仍有检查。
“played/阶段计时结束”不标为“实测机械到位”。运行中 CPU 下降幅度与命令率等待当前配对测量。

## GPU 缓冲图的准确画法

- 命令 bank：PS 打包 Scene，DMA 批量上传；已被渲染器占用的 bank 不被覆盖。
- 资源 bank：贴图/调色板/Tilemap 按代际生效；一个 Scene 引用一致的资源身份。
- 帧缓冲：渲染写后台，HDMI 扫描读前台；绘制完成后在消隐期交换。
- 回执：accepted、rendered、displayed 分别表示接收、绘制和真正呈现。
- 若表现上传与渲染重叠，需先核正式 BUILD_ID 与运行开关；视频/游戏互斥不代表所有在途事务自动消失。
- 不把 BRAM bank 画成外部 DDR，也不把原视频 RGB 分辨率与索引色逻辑帧分辨率混用。

## 评委关注点与对应证据

依据官方自主选题评分：创新性与应用价值 30，性能与资源优化 20，功能正确性与完整性 20，
大模型协作与技能包 15，文档质量与可复现性 15。以下为据此推导的展示重点：

- 单板为何需要 PL/PS 协同，硬件承担什么，PC 退出后系统还能完成什么（F01–F04）。
- 同负载下改进了多少、付出了多少资源、时序是否满足（F05、T01）。
- 除了成功瞬间，持续运行、模式切换、返回、断源恢复是否正常（F07–F09、T03）。
- 是否能由 Studio 从内容创作走到标准部署并复查结果（F06、T02）。
- Skill 从真实问题提炼且可复用：视频留一张短证据卡，报告与海报链接当前 skill/README.md；
  可展示“原测试漏检复位值→全输出校验定位到 5.001 ns”，不需要扩展成第九大演示模块。

## 三端统一制作规则

每个 F/T 编号保留同一事实来源和标题，输出可编辑 SVG/draw.io 与 PDF/PNG；视频在母图上
分步出现元素，海报取简化版，报告保留尺寸/协议/时序细节。坐标轴、单位、颜色、版本
和测量条件一致。PL、PS、外设、数据流、控制流固定配色及线型；不要让每一章重新定义。

性能图始终保留量纲、工况与测量平台：不要把微基准倍率、PC CPU-only 数据及集成
板端数据放成没有范围说明的一组柱子。避免用无统计定义的“流畅度百分比”和雷达图。

## 录制与采集

优先用摄像机同框记录真实手、HDMI 和实体手，记录机位帧率以确定时间分辨率。
已有软件记录只取正常缓存的时间戳/计数；附加测量单独安排，避免在真人演示中高频读取
MMIO、位置反馈或增加持续探针。CPU 指标注明“单核归一、双核最高 200%”或其他一致口径。
对跟随延迟分开记录识别、调度等待、发令、机械运动，不把既定 3 秒窗口误写为 CPU 卡顿。

当前为绘制和采集规划，未进行新的板测或机械动作。旧视频大纲中“Skill 为空”“缺顶层
Vivado 工程”已过时；以当前独立工程、skill/README.md 及 missing_items.md 为准。
