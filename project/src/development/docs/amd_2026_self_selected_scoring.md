## 评测指标与权重

对应来源第 3.3.5.5 节，[本地原文评分表](amd_2026_track_guide.md#L634)：

| 评测项 | 权重 |
| --- | --- |
| 创新性与应用价值 | 30 |
| 性能与资源优化效果 | 20 |
| 功能正确性与设计完整性 | 20 |
| 大模型协作与技能包 | 15 |
| 文档质量与可复现性 | 15 |
| 合计 | 100 |

> 两组采用同一套评测项与权重，但分组独立排名、独立评奖，评分时结合各自组别的考察侧重把握尺度。各项均含评委评定成分；功能正确性与可复现性两项以提交物核查与实测数据为主要依据。

## 组别与考察侧重

对应来源第 3.3.1.1 节，整理如下：

| 组别 | 参赛资格 | 考察侧重 |
| --- | --- | --- |
| 初级组 | 大学一年级至三年级在读本科生 | 逻辑设计、状态机、时序约束、接口协议等基本 FPGA 设计能力 |
| 高级组 | 大学四年级本科生及在读硕士生、博士生 | 在上述基础上进一步考察软硬件协同与器件整体性能的发挥 |

混合年级或学历队伍按其中最高者归入高级组。两组设计任务、提交内容与评测指标一致。

## 技能包评价与加分

对应来源第 3.3.5.2 节：

> 评价标准是可复用性：一支陌生队伍拿到该目录，能否直接用在自己的题目上。每一项须写明适用场景、使用方法与已验证的效果，并说明是从哪些失败或观察中总结得出。

> **通用 PYNQ Skill 单独加分。** 若提交的 Skill 面向 PYNQ 框架且不与本队题目绑定（换题目、换板卡仍可用），在本赛道评分中另行加分，见 3.3.2。

本指南说明了额外加分条件，具体加分数值以赛事方后续评分细则为准。

## 提交要求速查

以下是第 3.3.3 至 3.3.5 节的摘录整理，完整条款见下载原文：

- 工程：完整源码、可复现构建脚本、仿真或验证结果、综合与实现报告、上板运行脚本、实测输出与参考比对数据。
- 性能：目标器件上的实测性能和基线对比；报告资源占用、时钟频率与关键性能指标，以及优化前后性能和资源对比。
- 大模型协作：提交提示词、模型回答、自我纠错轨迹及智能体工作流设计（如有）。
- 技能包：置于 `skill/`，说明适用范围、使用方法、失效条件、已验证效果及提炼来源。
- 报告：选题背景与创新点、设计原理与功能框图、软硬件划分依据、接口设计、优化过程和从零复现步骤。
- 开源：GitHub 或 Gitee；采用允许再分发的开源协议，指南推荐 MIT 或 Apache-2.0。
- 文件命名：目录名与文件名使用纯英文小写字母、数字、下划线或连字符；正文可使用中文。采用其他目录组织方式时，在项目 README 中提供对照说明。
- 工具版本：推荐 Vivado / Vitis 2026.1，或 2025.2；其他版本须在报告中说明并保证脚本可复现。
- 实板：作品须在板上跑通并提供实测输出，提交物声明具体器件型号。
