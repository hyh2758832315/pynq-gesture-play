# PYNQ 开发技能包报告

日期：2026-11-01
交付包版本：0.2.2；PL 校验器 0.1.0，经验卡片 0.1.0
署名：

## 解决的问题

PL 优化后的数据包结果正确，并不意味着复位、空闲及无效周期的输出均与原版
一致。逐个手写参考实例和端口比较容易遗漏这些边界，验证材料也需要随工程交接。
本 Skill 将参考绑定、全部输出比较及原始日志判定组织为可重复执行的工具。

## 方法与提炼过程

工具读取冻结原版接口，为已有测试台生成参考实例；输入沿用实际 DUT 的端口，
参数逐项核对。时钟上升沿和下降沿后 1 ps 比较所有输出，检查复位和活动样本，
同时核验测试结束标志、实际结束事件与运行错误。源文件、配置及生成结果通过
SHA-256 关联，验证收据对应一次具体运行。

这一方法来自项目中的三类观察：包完成断言没有覆盖复位输出；参考实例与端口
比较需要重复编写；仿真进程正常退出时仍可能包含运行时 Fatal。因此将这些
判断固化为脚本，并保留正例、故障例和实际工具日志。

## 实验一：定位已有测试未覆盖的复位错误

对象为实际 PYNQ PL 数据包接收模块 `scene2d_upload_sink`。使用同一份未修改
测试台，发送字符串 123456789，核验 CRC、字节数和包数。设置三个输入：
原版用于绑定校准；A 只重命名内部寄存器；B 将复位时 completed_crc32 从 0 改为 1。

| 输入 | 原数据包断言 | Skill 全输出检查 | 观察 |
| --- | --- | --- | --- |
| 原版 | 通过 | 通过 | 完成参考绑定校准 |
| A：内部寄存器重命名 | 通过 | 通过 | 4 个输出、20 次采样比较通过 |
| B：复位值改变 | 通过 | 检出差异 | 5.001 ns 定位到 completed_crc32 |

B 的仿真日志出现 `PRESERVE_OUTPUT_MISMATCH`，校验命令返回 1，不生成通过收据。
这说明同一已有激励下，全输出比较补充了包完成断言的检查范围。
20 次采样包括复位及活动阶段，并非 20 个独立用例。

本实验由独立使用者根据包内说明完成，未修改工具或输入文件；交付者复核了
源码、原始日志和收据摘要。此次提交另提供可搬迁入口，方便直接复跑。
原始材料位于 [validation/evidence/consumer](validation/evidence/consumer)，
输入位于 [validation/inputs](validation/inputs)。

## 实验二：应用于实际 PL 优化验证

在 `scene2d_return_source` 返回源模块的资源优化任务中，工具复用既有测试并
加入边界激励，覆盖复位、停顿、部分数据拍、忙时启动等场景。附加检查完成
28,761 次全输出比较；原功能与资源门槛均通过。

| 项目 | 优化前 RTL | 优化后 RTL |
| --- | ---: | ---: |
| LUT | 89 | 89 |
| FF | 191 | 167 |
| BRAM / DSP | 0 / 0 | 0 / 0 |
| 10 ns OOC 综合后内部建立裕量 | +3.612 ns | +3.612 ns |

这里的资源变化是 RTL 优化结果；Skill 的作用是为该优化提供可复用的保持性检查
与可追溯记录。数据来自 Vivado 2026.1 综合报告，
材料位于 [validation/evidence/return_source](validation/evidence/return_source)。

## 复用方式

Python 3.11 与 Vivado/XSim 2026.1 为本次执行环境，器件为 xc7z020clg400-1。
新题目提供原版、改动版与现有测试台，通过 JSON 配置指定顶层、实例、时钟、
复位、参数和器件后即可复用。包内计数器示例不依赖本项目源码；实际上传模块
实验也提供完整输入和一条复现命令。

支持单时钟自包含叶模块的有限激励采样比较。源码共享宏、子 IP 和复杂类型等
超出当前解析范围时，工具在生成前提示；应选择适合该模块的验证方法。
有意修改接口或周期行为时，应按新规格建立预期结果。

## 提交对应关系

官方允许以校验脚本、工作流或案例模板提交技能包，并强调陌生队伍能否复用。
本目录提供 SKILL.md、脚本、配置、示例、实测记录和复现入口，围绕 PL 黄金参考
比对展示这一能力。来源与文件摘要见 validation/provenance.json。

## 交付复核

最终交付目录搬迁后再次运行实验一，共完成六次实际 XSim 仿真。原版和 A 的
全输出检查通过，B 的指定差异被检出，三个原数据包测试通过，输入文件摘要
保持一致。复现入口将所有预期汇总为 PASS；原始命令、日志和结果一并归档。

## 工程经验卡片的集成

项目中已归纳的重复问题整理为 20 张卡片，保留原案例 ID，按五类症状调用。
工具调用类覆盖判重、会话身份、版本参数和领域结果；制品类覆盖构建文件集、
地址传播、解析视图和正式导出；启动类覆盖就绪分层、依赖、入口及界面响应；
交接类覆盖幂等释放、代际和恢复；输入类覆盖最新状态消费及不同语义通道。

每张卡给出症状、核对与处理、完成条件和适用条件，并连接到随包携带的来源
快照。模型按当前症状加载对应组，直接利用已有经验进行定位；来源记录用于
需要时追溯。本次集成沿用已归纳的事实与处理方法，完成了卡片映射、链接和
文件摘要检查。

入口见 [pynq-debug-cards/SKILL.md](pynq-debug-cards/SKILL.md)。前述 PL 仿真实验
继续作为校验脚本的效果证据，经验卡片提供日常问题定位时可直接调用的知识。
