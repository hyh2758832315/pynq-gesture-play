# 实时输入与消费边界

按当前症状选择卡片，先核对触发条件，再采用对应处理。

<a id="h17"></a>
## H17 · 忙时切了手势，空闲后却不执行

- **症状：**MOVING 时见过最新帧，READY 后把同一新鲜帧当 duplicate 丢弃，必须移开手才恢复。
- **核对与处理：**分开“已观察”和“已消费”；忙时只保留最新槽，READY 时按当前来源身份、原始 source_at 和动作资格消费最新有效状态。保持相同姿态时避免重复下发。
- **完成条件：**完成前到达的最后一帧无需补发即可在可执行边界生效，且不会重复播放或积压旧动作。
- **适用条件：**重复读取保持原始源时间；过期或换源时清理旧状态。保持时长等策略由当前产品合同决定。
- **来源：**[来源案例](../sources/latest_input.txt)。

<a id="h18"></a>
## H18 · 边缘位置失效把可靠手势也清掉

- **症状：**手圈仍可见，分类正确，但 FRAME_EDGE、control.valid=false 被统一当无手/default。
- **核对与处理：**分别处理位置授权、同帧分类、UNKNOWN 与明确 NO_HAND；可靠分类可按产品规则独立传给被动跟随，保留来源身份、帧号与原始时间。
- **完成条件：**方向无效不会误删仍可靠的分类；明确无手与不确定输入执行各自策略。
- **适用条件：**位置和分类保持同帧身份；错误、时间断层、换源及暂停恢复后，通过新鲜度检查重新建立有效输入。
- **来源：**[来源案例](../sources/latest_input.txt)。
