# PYNQ-Z2 button-only R22 work record (2026-10-24)

Target: PYNQ-Z2 `xc7z020clg400-1`, Vivado 2026.1. User intent: retain the R21 large, bright hand marker; remove active sound sampling and HDMI volume bar; use BTN0 for the former low trigger and BTN1 for the former high trigger. Keep vision and HDMI OSD independent of game rendering.

The authoritative frozen source is `deliveries/c6i-pl-vision-volume-osd-r21-marker-r02-20261023`. Its Vivado source project was copied into `D:/vvg_button_only_r22`; the original `E:/vvl/c0e` and the Copilot hand project were not changed. The button software candidate is staged in `D:/vvg_button_only_package_stage`, currently **not deployable** because its hardware and manifests are still the old R21 identity.

Implemented:

- OSD pixels preserve R21's radius-48 green / radius-32 red fist circle, with the right-side volume meter removed. The OSD control no longer maintains audio freshness.
- PL replaces `voice_volume_0` and `audio_mclk` with 2-bit input AXI GPIO at `0x43C10000`, plus two flip-flop synchronizers. BTN0 maps to D19, BTN1 to D20. Audio ports and audio pin/clock XDC were removed from the isolated project. New BUILD_ID is `0xC0060F00`.
- PS candidate uses a 4 ms independent GPIO poller with three-sample debounce and edge queue. Hand OSD runs independently at 30 Hz with all former sound register fields zero. Game1 uses BTN0 shield / BTN1 attack; Game3 uses BTN0 lift / BTN1 gate; Game2 remains hand-only. Three new `.vvg` packages target the new BUILD_ID.

Evidence already obtained:

- Full non-incremental synthesis: `D:/vvg_button_only_r22/synth_receipt.txt`, PASS, 0 errors / 0 Critical Warnings.
- XSim: `BUTTON_OSD_PIXEL_PASS`; legacy audio-valid/level bits set high do not draw a meter; green normal and red fist markers render.

Its routed DCP is `D:/vvg_button_only_r22/c6_latency.runs/impl_button_r22/c6v_wrapper_routed.dcp`; `route_timing.rpt` reports WNS -0.497 ns and WHS +0.050 ns. The limiting path is in the inherited `gp0_smc` AXI address router, not the new button or OSD logic. DRC and OSD bus-skew checks have no blocking violation. Post-route `phys_opt_design` completed, improving final WNS to -0.031 ns, WHS +0.033 ns; final DRC has no errors. The resulting bit/XSA is retained only as diagnostic evidence and **must not be programmed** because timing still fails by 0.031 ns across six endpoints. `route_button_incremental.tcl` was started with the frozen R21 timing-closed checkpoint as reference.

R23 full implementation finished on 2026-10-24. The original post-route physical optimization left only one setup failure: WNS -0.072 ns, from external `vid_hsync` to `video_in/FORMATTER_INST/de_1_reg/D`; WHS +0.050 ns. Using a separate VS Code Vivado MCP session, a shortest-delay reroute of just this pin repaired setup but caused WHS -2.837 ns, so that experiment was rejected. Reloading the original checkpoint and rerouting the same pin with `route_design -pins $pin -auto_delay` gave accurate WNS +0.011 ns, WHS +0.050 ns, WPWS +0.538 ns, 0 unrouted/error nets, bitgen DRC 0 errors, and bus-skew constraints with positive slack. The repaired DCP, reports, bit and XSA are in `D:/vvg_button_only_r23b/timing_audit/`. Its XSA was exported directly from the repaired DCP. The external bit and XSA member have equal lengths and identical configuration payload; only bitstream header metadata differs because Vivado generated them at separate times. The source-to-repair command is recorded in `close_timing_shared_id.tcl` for replay. **Timing margin is 0.011 ns**, so any source/constraint change requires fresh signoff.
