# PYNQ 工具与制品观察摘要

按 E01–E12 对应技术卡片；仅保留归纳方法所需的技术观察。

## R01 / E01：阶段变化与命令判重

- 事实：声音迁移先综合，再改变阶段变量；同一 `source` 文本被短期判重，命令 52 返回 `SKIPPED (duplicate)`、`code=0`、`elapsed=0`。命令 53 实际执行，124.293 秒并取得新 route 标记与检查点。

## R02 / E02：工具、命令与领域结果分层

- 事实：声音仿真在正常 MCP 通道中返回 Fatal；准备过程的 `error_count` 包含关键警告。视觉报告生成 `code=0`，领域报告仍有 DRC 或时序失败；捕获异常的编码器探针退出 0，初始化结果仍 FAIL。

## R03 / E03：会话与任务计划身份

- 事实：声音会话已绑定计划，向 `global` 更新返回 `no plan found`；原始调用 `tc-muuz563l-e` 的 outcome为error、success为false、tcl_exit_code却为0；使用真实会话 ID 更新成功。

## R04 / E04：实际版本能力优先

- 事实：当前 Vivado 缺少 `list_property_values`，旧文档优化选项 `-O` 在该 XSim 被拒绝；实际元数据与本机帮助纠正调用后烟测恢复。PYNQ-Z2 / Vivado 2026.1 的独立GPIO微工程还显示：原请求的无前缀数值 `0` 被 `IP_Flow 19-3478` 拒绝，改成 `0x00000000` 才获得同目标读回。诊断接口导入猜测也曾在板端提前失败。

## R05 / E05：文件存在与工程注册分别检查

- 事实：冻结 header 实际存在且被 include，但未加入候选文件集，报 `filemgmt 56-591`；注册后 SKN6 解析成功，续接在另一个 DMA 时钟连接处失败。PYNQ-Z2 / Vivado 2026.1 独立微工程再次复现：同一原模块在缺 header 时引用失败，注册后引用成功；`.xpr` 的 `sources_1` 标为 `Verilog Header` 且供综合使用，但 `get_files -compile_order sources -used_in synthesis` 没有把它列为独立编译单元。

## R06 / E06：配置传播与生成制品复验

- 事实：BD 地址已更正，生成工具却返回 up-to-date；HWH 仍有旧地址，结构化预检明确拒绝。授权强制生成后，同一检查通过。GP0 参数初始读回正确，连接传播后仍曾改变。

## R07 / E07：解析器分支与邻接 XSA

- 事实：该 PYNQ 3.1 安装版按同 stem XSA 切换解析分支，却向 Metadata 传入 bit 路径，下载前抛 `UnknownInputFileExtension`。保留原制品，在隔离目录放入 SHA 一致的 bit/HWH 后，元数据纯解析通过。

## R08 / E08：IRQ 的持久与运行视图

- 事实：同 HWH 的原生解析有 IRQ，现代视图为空；嵌套 update 后返回的 copy-on-read 视图仍为空，r6 下载前断言失败。修复持久 parser 并重建运行描述后，r7 三层视图检查通过。

## R09 / E09：冷启动就绪与稳态期限

- 事实：旧编码器启动期限 5 秒；同函数无硬件 spawn 探针在新部署实际 8.618630578 秒就绪，随后正常关闭。新部署显式延长启动期限后该项通过。

## R10 / E10：依赖角色与实际解释器

- 事实：板端缺运行依赖 collision；随包携带固定发行源码与元数据、核版本/路径/SHA后 check-only 通过。tomli_w 属于 PC 打包依赖，同一板端入口无需它。

## R11 / E11：故障保留与关闭屏障

- 事实：r3 sink poisoned 后保留 owner；操作者确认唯一故障实例、已完成票据与 DMA idle，在专属许可下停止该通道并读到 Halted，随后才退出进程。后续切换先取得 cleanup_confirmed 与锁/端口释放证据。

## R12 / E12：部署入口与完成证据

- 事实：日常入口缺少平台/端口/源绑定，行为与显式验收入口不同；修复后真实 HTTP 回传通过。r8 真实帧、live 游戏和 GPU 完成回执已取得，真人方向、现场 HDMI 与长稳态仍待验。
